# Automatic thumbnails

Automatic thumbnails are enabled by default in Settings → Thumbnails. Startup backfill queues only indexed videos that have no detected preview. Existing artwork is reused immediately; scans, imports, and realized browser rows queue new or changed sources. Clearing the cache explicitly rebuilds previews for existing database paths. Media in rows actually realized by the browser and the selected details item are prioritized. Collection covers use the first ordered lesson or episode, even while later previews finish; covers do not cycle through completed children. One extraction runs at a time, independently of scanning and playback, using two decoder threads and a short accelerated sample. New import requests are serviced during startup backfill. Automatic reads, extraction, and publication yield while foreground page loads are active and for a short quiet interval after navigation; foreground loads never wait for that worker. Completed previews update existing card bindings in small batches without reloading the library, discarding loaded pages, or changing scroll position. Refreshing an image at the same path keeps the displayed image until its replacement is ready.

Returning from a media page reuses the existing Library view, including its virtualized cards, loaded pages, scroll offset, and decoded thumbnail sources. The hidden library is collapsed and does not recalculate its layout or request additional pages. Saved playback updates read only changed media’s playback fields and the affected collection, then update existing cards without refreshing folders or recreating artwork. Playback-based filters and sort orders query the browser again when their results need to change. Explicit refreshes, scans, and metadata changes still refresh affected library data.

Artwork priority:

1. A manually selected image, including images outside the video’s folder.
2. An image beside the video with the same basename, such as Inception.jpg beside Inception.mkv.
3. A poster image in that same folder.
4. A folder image in that same folder.
5. A generated video frame.
6. The existing media-type placeholder when a preview cannot be created.

Supported local artwork extensions, in lookup order: JPG, JPEG, PNG, BMP, GIF, TIF, TIFF. Names and extensions are matched without regard to case. Shared artwork applies to each video in the folder unless a matching filename or manual image takes priority. Parent folders are not searched.

Extraction uses the already packaged LibVLC decoder, with no extra executable to install. It starts around 10% into the video (at the beginning for clips shorter than a second), and chooses the most visible and detailed of four nearby frames. It samples further through dark frames, up to 32 frames, before falling back. Extraction has a 15-second timeout, creates no playback window or sound, and never writes playback progress or changes the original file. Very dark, unreadable, or unsupported files retain their placeholder. Failed automatic extraction is deferred for five minutes while the source remains unchanged; explicit regeneration bypasses this delay.

Generated JPEG previews fit within 480 × 270 while preserving display proportions. They are stored under %LocalAppData%\Scriptorium\GeneratedThumbnails\v1. Cache keys include source path, file size, and last-write timestamp, so unchanged videos reuse their previews. Writes are atomic; failed regeneration keeps the working preview. Old variants are removed after a replacement is persisted, and the generated cache is trimmed to 512 MB. Evicted previews are rebuilt when queued again. The existing resized-artwork cache remains separate. Both caches avoid enumerating the full directory for each preview; older untracked resized variants are reclaimed by scheduled cleanup.

The media editor includes Choose image, Restore detected, and Regenerate thumbnail. Regeneration refreshes automatic artwork and preserves a manual image. To return from a custom image to an automatic preview, restore the detected thumbnail first. Local artwork still takes priority during regeneration. Adding or changing local artwork is picked up on the next scan, startup, or regeneration.

Settings → Clear thumbnail cache clears both generated and resized previews. Source media and local artwork are preserved. Automatic previews are queued for recreation when the feature is enabled. Turning automatic thumbnails off keeps existing artwork and allows explicit regeneration.

Verification: run dotnet test Scriptorium.sln. AutomaticThumbnailServiceTests cover artwork priority, cache reuse, source changes, failures, startup backfill, disabling, cache clearing, and concurrent manual-image, playback, and scan updates. ThumbnailGenerationTests decode the packaged MP4 fixture, verify dimensions and proportions, confirm source bytes and file handles are preserved, and check cancellation. LibraryBrowserCardsRowTests verify stable, lazy card instances. The WPF thumbnail smoothness resource check uses 200 media items and asserts unchanged rows, loaded pages, scroll offset, stable course covers, and image swaps without a blank frame. It also switches away and back twice, verifies identical library controls and decoded images, saves movie/lesson/episode progress while away without resetting rows, and checks that playback sorting and completion filters still update. StartupResponsivenessTests deliberately slow synchronous SQLite reads and block a folder check while navigating all five tabs, assert that reads stay off the UI thread and input remains responsive, and check that recently loaded tab data is reused.
